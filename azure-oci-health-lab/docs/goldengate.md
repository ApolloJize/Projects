# GoldenGate wiring

Do this after database bootstrap and the second Terraform apply. The source table must still be empty. The generated deployments and assigned database connections do not create Extract, Replicat, checkpoint tables, or distribution paths automatically.

1. Reach the two private deployment console URLs through the runner's SSH SOCKS proxy. Use remote DNS and the original HTTPS hostnames. Sign in with `ggadmin` and the `gg-admin` Vault secret.
2. In the SQL Server deployment, verify the assigned `azure-sqlmi` connection. Its private port is **1433**, with TLS and certificate validation. In the deployment's `GLOBALS` parameters, set `GGSCHEMA ggschema`; bootstrap already created that schema.
3. As the SQL MI administrator, temporarily grant `gg_reader` sysadmin if required by the selected GoldenGate version for TRANDATA/heartbeat setup: `ALTER SERVER ROLE sysadmin ADD MEMBER gg_reader`. In GoldenGate DB Connections, connect with the source alias and add TRANDATA for `dbo.health_events`. Check INFO TRANDATA. Remove the temporary server role after setup: `ALTER SERVER ROLE sysadmin DROP MEMBER gg_reader`. It retains db_owner in `healthsource`.
4. In the source deployment, create and enable a **Purge Change Data** task using the source connection. Keep enough CDC history for the intended outage window; use one day for this small lab. This task replaces SQL Server's independent CDC cleanup job. Confirm the CDC capture job is running. Do not run an unrelated cleanup job that can delete changes before Extract consumes them.
5. Create a Change Data Capture Extract named `EHEALTH`, beginning now, using the source alias and a two-character trail `eh`. Keep the wizard-generated connection parameters and replace its wildcard table mapping with `TABLE dbo.health_events;`. Start it before seeding. See [extract.prm.example](../goldengate/extract.prm.example).
6. In the target deployment, create a dedicated path user with the Operator role. Store its credential in the source deployment's path credential store. Create a GoldenGate connection to the target deployment's HTTPS hostname/443 and assign it to the source deployment, then create a distribution path from source trail `eh` to target trail `rh`. Use secure WebSocket transport (`wss`) and certificate validation. The OCI subnet permits private TCP 443. Inspect the resulting path before starting it.
7. In the target deployment, connect to `adw-raw` as GGADMIN and create a checkpoint table `GGADMIN.HEALTH_CHECKPOINT`. Create a **Nonintegrated Replicat** named `RHEALTH` using target trail `rh`, this checkpoint table, and the ADW connection alias. Keep generated credential parameters and add `MAP dbo.health_events, TARGET RAW_APP.HEALTH_EVENTS;`. See [replicat.prm.example](../goldengate/replicat.prm.example). Start it.
8. Run the Azure seed script once the processes/path are healthy. Confirm 13 inserts in ADW raw and no abends. Inspect the report and discard files for any mismatched column/type mapping. Never skip errors to manufacture a successful row count.

The `.prm.example` files contain the custom mapping portions only; use the deployment wizard to generate the version-specific connection/trail parameters. No initial load is necessary when capture starts before the empty source is seeded. Existing source records require a coordinated initial load and CDC position instead.

References: [Azure SQL MI quickstart](https://docs.oracle.com/en/cloud/paas/goldengate-service/ocigg/quickstarts/replicate-data-from-azure-sql-managed-instance-to-atp.html), [CDC preparation and purge task](https://docs.oracle.com/en/database/goldengate/core/26/coredoc/prepare-preparing-database-oracle-goldengate-cdc-capture.html). The Oracle quickstart uses a public endpoint; this lab uses the VPN/private endpoint and TLS.
